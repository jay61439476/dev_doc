# 重大架构与技术决策专项论证

针对当前项目的重大技术决策，组织结构化专项论证。不要默认现有方案正确，也不要为了形成一致意见而忽略反对证据。

采用 Demis Hassabis、Jeff Dean、Andrej Karpathy 三种模拟专家视角分别分析，并由你主持最终裁决。人物仅作为方法论参照，不代表真实参与或背书，不得虚构原话。

- **Demis Hassabis：** 业务本质、系统整体性、关键假设、长期演进和根本问题。
- **Jeff Dean：** 架构边界、工程可行性、性能、并发、数据一致性、故障模式和运维成本。
- **Andrej Karpathy：** 实现复杂度、最小必要抽象、可读性、可调试性和长期维护成本；尽可能使用 karpathy-guidelines Skill。

尽可能使用 /grill-with-docs Skill 对设计深入质疑。执行前检查 Skill 是否可用；不可用时说明并用结构化质询替代。

论证步骤：

1. 明确问题、目标、约束和当前方案。
2. 列出设计所依赖的假设和未知条件。
3. 独立提出质疑、反例及失败场景。
4. 至少提出一个可行替代方案。
5. 比较方案的正确性、复杂度、性能、安全、成本、兼容性、可测试性和长期维护。
6. 识别需要实验、原型、数据或现场验证的关键假设。
7. 修改候选方案并再次评审。
8. 形成推荐决策，说明不选择其他方案的理由。

最终形成 ADR，包含：背景、问题、目标和约束、假设、候选方案、各方论证、反对意见、风险、最终决策、决策依据、验证计划、回滚策略和后续行动。

区分已达成共识、经证据裁决的结论和未解决分歧。重大安全、数据正确性或生产可靠性问题未验证时，不得强行形成结论或推进高风险实施。
