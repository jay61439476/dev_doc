# 软件项目迭代总结与下一轮规划

请基于最新 Git Commit、PR、Issue、代码变更、文档和真实测试结果，对当前迭代进行客观复盘。不得只依据工作汇报。

采用 Demis Hassabis、Jeff Dean、Andrej Karpathy 三种模拟专家视角复盘：
- Demis Hassabis：整体方案、业务问题是否解决、架构是否改善及长期影响。
- Jeff Dean：工程质量、系统可靠性、性能、数据正确性和故障处理。
- Andrej Karpathy：代码是否简洁、易懂、易调试，是否引入不必要复杂度；尽可能使用 karpathy-guidelines Skill。

核实并说明：

1. 本轮目标、范围和验收标准。
2. 实际完成的功能、代码、配置和文档变更。
3. 技术方案变化及其决策依据。
4. Commit、PR、Issue 的真实状态。
5. 实际执行的测试、结果和覆盖范围。
6. 前后端启动、页面、API、数据库等验证结果。
7. 已解决问题、新发现问题和可能回归。
8. 未执行或未通过的测试及原因。
9. 当前风险、外部依赖和阻塞。
10. 是否满足验收标准，是否允许进入下一阶段。

将成果和遗留事项记录到项目文档及对应 Issue。区分已完成、部分完成、未完成、已验证、未验证和阻塞；不可将计划中的工作描述成完成。

最后制定下一轮计划，按优先级列出任务、依赖、负责人（若已知）、验收标准和风险。涉及生产安全或数据完整性的未解决 P0 问题时，不得建议进入相关发布或切换阶段。
