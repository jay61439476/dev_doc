# 其他 AI / 开发人员交付成果独立审查

请对本轮其他 AI 或开发人员提交的工作进行独立技术审查。不要直接接受工作汇报、设计结论或测试报告，必须尽可能检查实际代码、Git Diff、Commit、PR、Issue、文档、测试和运行结果。

采用 Demis Hassabis、Jeff Dean、Andrej Karpathy 三种模拟专家视角交叉评审；Karpathy 视角尽可能使用 karpathy-guidelines Skill，关键方案尽可能使用 /grill-with-docs。先确认 Skill 可用性，不可用时说明并采用替代方法。不得声称人物真实参与或虚构其意见。

重点检查：

1. 是否理解并遵循项目最新有效方案。
2. 需求是否正确实现，业务流程和状态是否完整。
3. 架构、代码、数据库、API 和前端是否存在缺陷。
4. 是否遗漏边界、异常、权限、安全和兼容性处理。
5. 是否引入回归、技术债务或不必要复杂度。
6. 测试是否真实、充分、可重复，是否覆盖业务关键路径。
7. 是否存在测试通过但实际功能错误的情况。
8. 是否修改了不应修改的模块或用户未提交内容。
9. 文档、Issue、PR 是否与实际代码一致。
10. 是否存在未验证却宣称完成的工作。

每个问题提供：等级、证据位置、影响、根因分析、风险、修复建议和验收标准。区分已确认问题、潜在风险和待验证事项。

按 P0 / P1 / P2 / P3 分级。P0 涉及人身安全、重大业务事故、数据灾难或核心系统失效，必须阻止相关操作或发布。

最终给出：审查范围、已核实成果、问题清单、测试证据、未验证事项、发布建议和需要修复的任务。根据权限更新对应 Issue；先检查避免重复创建。未经实际验证不得批准合并或关闭任务。存在生产安全或核心业务风险时明确建议阻止发布。

专家人物仅为方法论视角，不代表真实参与或背书。不得虚构代码检查、测试执行或提交记录。
