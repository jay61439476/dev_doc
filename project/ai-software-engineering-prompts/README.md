# AI 软件工程评审与迭代提示词

一套面向软件项目的可复用 AI 工程提示词，覆盖项目评审、方案论证、功能开发、代码复核和迭代管理。适用于 Codex、Claude Code、OpenCode 及其他具备代码库访问能力的 AI 开发工具。

## 目标

将 AI 辅助开发从“单次回答或代码生成”转变为可追踪的工程闭环：

**调查现状 → 专家视角评审 → 质疑与论证 → 制定方案 → 实施修改 → 独立验证 → 修复复测 → 文档与 Issue 沉淀 → 迭代复盘**

## 快速使用

1. 首次接手项目：使用 01，先完成项目调查和全面评审。
2. 评审其他 AI 的产出：使用 03，独立核验实际代码和测试。
3. 开始功能开发：使用 02，持续推进到可验证的交付。
4. 修复完成后：使用 04，检查修复是否有效及是否引入回归。
5. 每轮结束：使用 05，更新项目记录并规划下一轮。
6. 重大技术选型或架构调整：使用 06，形成 ADR。

每份提示词可独立使用，也可以组合使用。将稳定的项目约束（技术栈、代码规范、测试命令、安全边界、部署流程）放入项目自己的 AGENTS.md 或同类说明文件，不必反复写入每轮提示词。

## 专家视角说明

提示词使用 Demis Hassabis、Jeff Dean、Andrej Karpathy 作为公开专业方法论的参照视角，属于模拟式角色框架，不代表这些人物真实参与、认可或背书，也不得虚构其原话。

其中 karpathy-guidelines 与 /grill-with-docs 是可选的外部 Skill 名称。执行前应检查当前 AI 工具是否实际安装并可用；不可用时必须明确说明，并使用提示词中规定的替代审查方法，不得声称已经调用。

## 使用边界与安全

- 所有结论以实际代码、配置、测试、日志和可复现证据为依据，不得虚构审查、测试或执行结果。
- AI 可以分析、修改和验证其有权限操作的开发资产；对生产环境、数据和设备的操作必须遵守项目授权流程。
- 涉及真实设备、搬送系统、AGV、输送机、机械臂、PLC 或人身安全时，必须区分开发、仿真、测试和生产环境。环境不明确时禁止执行可能影响生产的操作。
- 不得绕过急停、安全联锁、设备权限或其他安全保护。软件测试通过不能代替设备安全评估和现场验收。
- 对重大分歧、未验证前提和环境阻塞应如实记录，不得为了形成共识而掩盖风险。
